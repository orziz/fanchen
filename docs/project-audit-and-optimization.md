# 项目梳理与优化记录

## 当前架构

- `src/config`：静态世界、剧情、教程、动作和数值定义。
- `src/stores/game`：Pinia 游戏状态、初始工厂、存档水合与上下文适配器。
- `src/systems`：世界推进、战斗、NPC、交易、剧情等领域命令。
- `src/core`：不依赖 Vue 的纯规则，包括整数成长余量和当前要务决策。
- `src/components/v1`：唯一游戏壳层、状态栏、工作台、操作坞和工具导轨。
- `src/components/panels`：各玩法系统的可见工作面板。
- `src/tools`：内容编辑工具，与游戏运行界面分离。

## 本轮关键结论

### 界面

备用界面缺失真实背包、教程锁、存档、速度和策略控制，继续双线维护会制造错误信息和行为分叉。本项目只保留完整的 v1 壳层，并删除模式切换、v2 组件和相关样式。

首屏新增持久的“当前要务”层，统一教程、剧情、战斗、旅程、状态、冲关和长期策略的下一步提示。工作台改为只挂载当前面板，避免九个隐藏面板同时运行计算。

### 游戏规则

手动操作统一调用 `performAction`，系统层校验教程锁、剧情、战斗、地点和冲关条件。调息不再由组件直接改资源。NPC 传闻可用性查询不再消耗随机数。

整数状态继续作为存档事实，小数奖励存入 `migrationFlags.numericCarry`。重复规范化不会再抹掉 `0.8` 修为、`0.3` 冲关等累计进度。

### 剧情与时间

开场剧情始终使用可见遮罩，不再转入没有渲染器的 rail 状态。遮罩阻断背景指针操作、锁定键盘焦点，并在关闭后恢复原焦点。剧情遮罩和隐藏浏览器标签页都会暂停自动世界推进。

### 存档

保存前保留上一份有效快照；主档损坏时优先恢复备份。读取会修复未知地点、失效剧情节点和旧展示模式，重开后立即保存新周目。`migrationFlags.saveVersion` 标记当前内部存档代际。

## 验证基线

- `npm test`：纯逻辑与系统回归测试。
- `npm run typecheck`：TypeScript 全项目检查。
- `npm run build`：IIFE 发布构建。
- `npm run test:visual`：使用本机 Chrome 自动走完开场教程，并检查 1440x900 与 390x844 视口、剧情暂停、横向溢出、背景资源和移动工具抽屉。

本轮构建从约 `943.23 kB` JS / `71.80 kB` CSS 调整为约 `938.38 kB` JS / `52.26 kB` CSS。山水背景作为独立静态资源输出，不再内联到 CSS。

## 保留边界

- 随机事件仍使用全局 `Math.random()`，无法复盘同一随机序列。若要支持可重放战报、问题复现或确定性存档，需要引入带 seed 的 RNG 状态并迁移所有随机调用。
- 发布格式仍是单 IIFE 文件，Pixi.js 无法按路由拆包。若网络首载成为目标，需要增加现代 ESM 发布产物或改为标准应用构建；这会改变现有嵌入和直接打开契约。
- 当前存档以内部版本和水合修复保持兼容，尚未采用独立 envelope 与逐版本迁移管线。只有出现多版本长期共存或云存档需求时，再扩大这部分结构。
