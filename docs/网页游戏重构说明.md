# 凡尘立道录 · 网页游戏化重构说明

> 本文记录 2026-09 这一轮重构：把“信息后台式面板”改成有场景、人物、演出与声音的网页游戏。内容包括重构前的评估结论、表现层新架构、玩法与数值调整、扩展方法和验证方式。
> 题材与世界规则仍以 [修真题材长期总纲](./修真题材长期总纲.md) 为准，系统先后以 [修真系统分期总表](./修真系统分期总表.md) 为准，工程边界以 [project-rules.md](./project-rules.md) 为准，视觉细则见 [visual-design-spec.md](./visual-design-spec.md)。

## 1. 重构前的评估结论

- **挂机卡死**：自动调息不回体力，约 5 个游戏日后体力低于阈值就永久调息，修为停滞。
- **教程期停摆**：未投势力时，“小本营生”“外出闯荡”会选中被指引锁住的行动，时间不走、反复刷警告。
- **不像游戏**：主界面是十个页签、三条导轨、倍速与存档挤在一屏的信息后台；没有场景、人物、动画和声音。
- **节奏拖沓**：1x 每跳约 7.6 秒；纪事被陌生 NPC 的动态淹没；成长术语直接堆数字。
- **文案违规**：“策略盘”“系统逐步开放”“手动冲关线”等界面说明写进了游戏本体。
- **包体偏重**：Pixi.js 只用于地图，却占发布包的大头。
- **数值失衡**：战斗在任何境界都几乎打不赢；跑商利润滚雪球；默认打算“维生求进”只会打坐、几乎不挣钱；“苦修”会被引到没法打坐的星坠谷，冲关失败后一直歇息。

## 2. 表现层

### 2.1 舞台与缩放

- 以 1280×720 为基准：`html` 字号取 `clamp(9px, min(2.2222dvh, 1.25vw), 34px)`，即 1rem = 舞台高度 / 45。整屏等比缩放，不出现滚动条；所有尺寸一律用 rem。
- 布局：场景铺满全屏，其余元素浮在场景上——
  - 顶栏：名号与境界、灵石 / 声望 / 战力 / 悟性、日期与时辰天气、八本书册入口、存档与设置。
  - 左栏人物卡：境界与下一境、修为与火候、气血真气体力、兵器护甲心法、所投门路。
  - 右栏：要务卡（眼下该做什么 + 当前修行路标）与纪事（经历 / 传闻两栏）。
  - 底栏行动坞：当前所做、可做行动、挂机打算、暂停与倍速。
- 设备：桌面优先；手机横屏沿用同一套缩放可玩；窄竖屏只显示“请横置”提示，保证不坏。

### 2.2 画面阶段与设置

- `useGamePhase`：`title` → `playing`。标题页提供续游、新开一世（起名 + 选出身）、导入存档。
- 设置面板：音乐 / 音效音量、静音、减少动效、显示传闻、导出 / 导入存档；打开设置时时钟暂停。
- 设置单独存于 `fanchen_save-settings`，不进入游戏存档。

### 2.3 书册

- 八本书册以浮层打开：人物 C、行囊 B、山河 M、市集 T、营生 I、门路 F、人情 P、纪事 J；Esc 关闭。
- `composables/useBooks.ts` 管书册开合、页签与热键；旧代码里的 `setTab` 调用由 `useStage` 兼容层转给书册。
- 书册只调用系统层命令、读取 store，不复制规则。例：茶馆酒馆的风闻由 `systems/rumors.ts` 生成，地图书只负责呈现。
- 山河图改为 SVG（`components/books/map/`），支持拖拽、滚轮与双指缩放；不再依赖 Pixi.js。

### 2.4 场景美术（全部由代码生成）

- 不使用位图素材，也不需要美术出图；每个地点的画面都由种子随机数程序化绘制，同一地点每次画面一致。
- `src/art/scene/archetype.ts`：按地点的地形描述、标签和地区推导地貌原型（山形、水面、人烟、草木、炊烟、异象、积雪、田垄、冷暖）。自动推导不合意时，在 `OVERRIDES` 里为该地点补一行。
- `src/art/scene/compose.ts`：生成远 / 中 / 近三层可平铺画布。
- `src/art/scene/renderer.ts`：十二时辰光照、天气粒子、赶路视差、换景交叉淡化、打坐气旋、破境与受击闪光。
- `src/art/paint/`：笔触、山、水、草木、建筑、地面等绘制原语；`src/art/rng.ts` 为可复现随机数。
- `src/art/figures/`：主角 SVG 剪影（姿态随行动变化）与妖物剪影（按模板取形与体型）；`src/art/icons.ts` 为界面图标。
- 调试入口：`tools/scene-lab.html?loc=<地点id>&hour=<0-11>&weather=<天气>&travel=1&grid=1&figures=1`。

### 2.5 声音

- `src/audio/` 用 WebAudio 实时合成，没有音频文件。
- `music.ts`：五声音阶的生成式配乐，分标题、昼、夜、战斗四种情绪；`ambience.ts`：风、雨、虫鸣等环境声；`sfx.ts`：交互、战斗、破境音效。
- 受浏览器自动播放限制，玩家第一次点击或按键后才开始发声。

### 2.6 反馈与演出

- `useFx`：飘字、横幅（遇敌、破境、路标）、屏震、闪光、人物与妖物动作。
- `useGameFeedback`：把事件总线上的 `combat:*`、`player:breakthrough`、`milestone:completed`、`travel:arrived` 等事件翻译成演出与音效。规则层只发事件，不碰表现。
- 战斗在场景里演出：主角与妖物对峙，头顶血条与飘字，底栏换成出手 / 术法 / 守势 / 服药 / 撤走 / 自动。
- 纪事只播报玩家见过或听说过的 NPC 的动态。

## 3. 玩法与数值

### 3.1 时间

- 每跳是半个时辰；1x 每跳 3 秒（一日约 72 秒），可切 2x / 4x / 10x；交战时每跳间隔乘 0.55（最短 260ms）。
- 剧情遮罩、设置面板、页面隐藏和“手动操作”时，时钟不走；每 45 秒自动存档。
- 新局从卯时开局，天色不再一片漆黑。

### 3.2 修行路标

- `systems/milestones.ts`：11 个固定路标，从“扎稳底子”到“炼气有成”，覆盖修行、游历、战斗、跑商、心法、门路、置业、秘境。
- 完成记在 `story.flags` 的 `milestone.<id>`，给少量灵石、声望或物品（物品见 [item.md](./item.md) 第 10 节）；要务卡显示当前路标与进度。
- 路标是新手指引层，不替代世界状态派生的委托与机会（见 [自由度与世界自演阶段一方案](./自由度与世界自演阶段一方案.md)）。

### 3.3 出身

- `config/origins.ts`：田家子、猎户后人、货郎之子、落魄书生，只影响起步数值与随身物件，不锁任何门路。

### 3.4 战斗

- 敌手强弱由所在地的险度 d 决定（`config/combat.ts` 的 `getDangerBaseline`）：

  | 项 | 公式 | 险 1 | 险 2 | 险 3 | 险 4 |
  |---|---|---|---|---|---|
  | 气血 | 22 + 20(d−1) | 22 | 42 | 62 | 82 |
  | 力道 | 5.5 + 1.0(d−1) + 0.3(d−1)² | 5.5 | 6.8 | 8.7 | 11.2 |
  | 灵石 | 8 + 8(d−1) | 8 | 16 | 24 | 32 |
  | 修为 | 3 + 3(d−1) | 3 | 6 | 9 | 12 |

- 妖物模板只带相对倍率（皮厚、力大、真气足）与掉落门类；没有专属妖物的地方，从险度相近的四方妖物里挑。
- 设计口径：境界 r、未添装备的修士打险 r+1 的寻常妖物，五六招可胜、折损四成上下气血；带词缀的更凶，再高一级便凶多吉少。
- 秘境首领按所在地险度加一、皮厚力沉，所得三倍；势力追兵按“地点险度”与“境界加二”取高。
- 自动出招：估算胜负，若撑不到对手倒下且没有两成余裕、气血又低于七成，就趁早脱身；伤重时服下行囊里回气血最多的药食；有术法用术法。
- 亲手出招与自动出招一样，每个回合都让世界走过同样的时间。

### 3.5 挂机打算

下表为模拟结果：每种打算 4 局、每局 60 个游戏日（1x 约 72 分钟），开局已投青禾乡社。

| 打算 | 行为 | 练力 | 感气 | 30 日灵石 | 其他 |
|---|---|---|---|---|---|
| 苦修养气 | 只在能打坐、镇得住的地方打坐；灵气低时换地方；打坐练体所得 ×1.25 | 约 9 分钟 | 25–34 分钟 | 约 50 | 炼气约 67 分钟 |
| 维生求进 | 灵石低于 60 + 境界×90 时先跑差事、摆摊；宽裕后以打坐为主，间或跑腿 | 12–22 分钟 | 31–37 分钟 | 约 500 | 声望约 40，几乎不倒下 |
| 外出闯荡 | 只去险度不超过境界加一的历练地；气血不足七成半先歇 | 15–21 分钟 | 约 52 分钟 | 约 1900 | 声望约 160，60 日倒下 4–11 次 |
| 小本营生 | 压货跑商 | — | — | 约 9000 | 不破境 |

- 所有打算共用：底子与火候到线时，就近去险度不超过境界加三的灵地冲关；冲关受挫只折两成火候。
- 这组数字是调参依据，不是承诺；改动战斗、修行或经济公式后应重跑同类模拟（方法见第 5 节）。

### 3.6 经济

- 跑商：售价系数为 1.04 + 路段×0.022 + 供需与地盘加成；商道技能加成封顶 +12%（技能 30），本地声望加成封顶 +10%（声望 40）。
- 势力巡查差使的赏钱随势力阶与地方动荡度上浮。
- 兵器与护甲有最低境界（见 [item.md](./item.md) 第 4 节）。

### 3.7 存档

- 仍用 localStorage `fanchen_save`，保留上一份有效快照作为备份；迁移入口仍是 `stores/game/hydration.ts`。
- 导出为 JSON 文本文件。导入时先在候选副本上走水合修复，再校验各块字段的类型与新档一致、纪事 / 群像 / 行囊 / 产业 / 人情 / 功法 / 地盘 / 市集的每一项都读得动，并试算一遍派生属性；全部通过才落盘读入，任何一步失败都原样保留当前进度、主档与备份。

## 4. 目录变化

- 新增表现层：`components/GameRoot.vue`、`components/shell/`（顶栏、人物卡、要务卡、纪事、行动坞、打算浮层、设置、标题页、新局）、`components/scene/`（场景、主角、妖物、地名牌、战斗 HUD）、`components/books/`（八本书册及子视图）、`components/common/`（图标、墨条、印章头像、物件格、悬停提示）、`src/art/`、`src/audio/`。
- 新增规则模块：`systems/autoplay.ts`（挂机决策）、`systems/milestones.ts`、`systems/rumors.ts`、`systems/industryOrders.ts`（从 industry.ts 拆出的行会订单）、`config/origins.ts`、`stores/game/origin.ts`。
- 已删除：`components/v1`、`components/panels`、`components/ui`、`GameShellHost.vue`、`composables/useWindows.ts`、`src/pixi/`、`styles/legacy*`，以及 pixi.js 依赖。

## 5. 验证

- `npm test`：规则层回归，包括挂机调息回体力、修为持续增长、教程期时间照走、不会困在无法打坐的灵地。
- `npm run typecheck`、`npm run build`。
- `npm run test:visual`：用本机 Chrome 走完开场、检查桌面与手机横屏视口、书册、战斗与横向溢出（需先 `npm run build` 或设置 `FANCHEN_URL`）。
- 发布包以 file:// 双击 `dist/index.html` 实测。
- 数值模拟：在 Node 里用 vitest 直接驱动 `gameStep()`（写法参考 `systems/autoplay.test.ts`），多种打算 × 多局 × 60 日统计破境时间、灵石、胜负与倒下次数。

## 6. 已知边界

- 规则层的随机仍用全局 `Math.random()`，无法复盘同一局；场景美术用的是独立的种子随机数。
- 行商 30 日可攒约 9000 灵石，而最贵物品约 3200：中后期缺少花钱的去处，后续宜补家宅、委派、宗门建设等出口，而不是继续压低收入。
- 内容编辑器有三个文件在重构前就超过 500 行（`src/tools/story-editor/main.ts`、`src/tools/shared/storyFile.ts`、`src/styles/tools.css`），本轮没有改动。
- 窄竖屏只提供横置提示，不做竖屏布局。
